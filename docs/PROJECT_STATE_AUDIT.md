## 6. How the current gold decision is defined

ORACLE V2 (`configs/oracle_v2.json`): among candidates passing broad windows, preferred windows, NCO:OH 1.3–3.0, MDI 35–49 wt% of polyol+MDI, chemistry-in-domain and full-interval-inside-broad-window, minimise

`J = log10(eta80/3.4785)^2 + log10(eta120/0.4243)^2 + log10(ratio/8.1548)^2`

Verified locally: recomputing `J` from the compact snapshot reproduces `oracle_score` to 9e-17 and `mdi_fraction_total = mdi_parts/(100+mdi_parts)` to 2e-16. Gold `WO_INV_0579` (rank 1, J=4.16e-4) is consistent with the snapshot.

Design manifold (verified on the 928-row grid): `mdi_parts = k_blend * nco_oh` exactly, one `k` per blend. For blend PPG700:50+PPG1000:50, `k = 30.3875`, so the MDI-fraction floor 0.35 is crossed at **NCO:OH = 1.7720** (continuous) and the first reachable grid point is **1.8** (`WO_INV_0420`). `WO_INV_0419` (NCO 1.7) has MDI fraction 0.3406 < 0.35 and is infeasible. This part of the user's decision-frontier narrative is confirmed from real design data.

**Not verifiable locally:** that `WO_INV_0419` is the property-only optimum over all 928 candidates, and that `WO_INV_0420` is the robust winner. Both require the complete `PUR_SIM_V1` response columns (see §9/§10).

## 9. Potential answer leakage found

1. `results/oracle_v2/oracle_best.json` and `README.md`/`docs/WORKFLOW_V2.md` state the gold ID in plain text. Fine for the repo, but the Agent runtime must never be allowed to read the repo root. The cloud runtime reads only `benchmark/recover_v1/blind/`, which is correct; this pass adds a filesystem guard and a scan test.
2. `data/oracle_top30_compact.csv` contains `oracle_rank`, `oracle_score` and source IDs. It is not in the blind dir, but it lives under `data/`, which a careless "load everything under data/" would expose. The runtime guard now whitelists the blind bundle only.
3. `verify_no_leakage` existed only as a library function called by `build_blind_bundle.py`; there was no standalone script, no scan of prompts/task files, and no test that the *runtime-readable* file set is closed. Added.
4. `configs/recover_v1.json` (shipped inside the blind bundle as `benchmark_config.json`) contains `anonymization.component_columns = ["PPG400", ...]`. The builder pops the `anonymization` block before writing, so the bundle is clean, but the original material names also appear in `blind.drop_columns` semantics comments — popped as well. Verified by the new scan.
5. The system prompt and task JSON do not mention any ID or material name. OK.
6. No prospective wet-lab data exist in the repo yet; `data/prospective_validation/` is created with `agent_access=false`.
